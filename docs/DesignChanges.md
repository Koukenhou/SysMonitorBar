# 設計変更メモ（v1.0 からの差分）

`SysMonitorBar_Design_v1.0.md`（設計の基準）と `SysMonitorBar_Codex_Implementation_Prompt.md`（実装指示）に対する変更点。ここに書いた項目は、元の文書より優先する。決定日 2026-10-22。

## 1. KOU が決めた変更

| # | 項目 | v1.0 | 変更後 |
|---|---|---|---|
| D1 | GPU 使用率・専用 VRAM の取得元 | LibreHardwareMonitorLib | Windows のパフォーマンスカウンター（`GPU Engine`、`GPU Adapter Memory\Dedicated Usage`）と、総量取得用の DXGI。管理者権限・ドライバーは不要で、値はタスクマネージャーと同じ基準になる。MVP では LHM を使わない。温度は 2 期で、LHM を任意の追加機能として検討する |
| D2 | CPU 使用率の基準 | LHM の CPU Total Load（時間ベース） | `Processor Information(_Total)\% Processor Utility`（タスクマネージャーと同じ基準）。100% を超えた値は 100 として表示する |
| D3 | 画面の言語 | 簡体字中国語 | 日本語。文言は `src/SysMonitorBar.Core/Resources/Strings.resx`（既定のカルチャ＝日本語）にまとめ、後から言語を足せる形にする |
| D4 | 利用範囲 | 明記なし | 他の人にも配布する。ライセンスは MIT |
| D5 | 発行形式 | 未定 | win-x64 の自己完結型（self-contained）単一 exe |
| D6 | リポジトリ | — | `C:\KOU\_template` から作った独立した git リポジトリ（ブランチは `main`） |

D1 で LHM を外したため、v1.0 §12-10 の MPL-2.0 に関する義務は、現時点では発生しない。

## 2. 設計書の矛盾・あいまいな点の解消

- **指標 ID**：JSON には v1.0 §9 の文字列 ID をそのまま保存する（`cpu.usage`、`disk.C.usedPercent` など）。コード内では「種類（`MetricKind` enum）＋対象（ドライブ文字など）」の `MetricKey` に変換して扱う。読み取れない ID は読み込み時に捨てる。読み取れるが今は存在しないデバイス（外したディスクなど）の ID は、設定に残す。
- **区切り文字**：JSON の `separator`（文字列）をやめ、`showSeparator`（bool）にする。画面の「区切り線を表示」に合わせるため。区切りは ` | ` に固定する。
- **位置**：`relativeX/relativeY` をやめる。保存するのはモニター名（`screenDeviceName`）と、バー左上の座標（段階 C からは物理ピクセルの `leftPx` / `topPx`。§4 を参照）。バーの幅は表示内容で変わるので、左上を基準点にする。保存した位置が今あるどのモニターの作業領域にも入らない場合は、メイン画面の上端中央（上から 16 DIP）に戻す。
- **幅の揺れ**：数値はフィギュアスペース（U+2007、数字 1 桁と同じ幅）で桁数をそろえ、`9%` → `10%` のような変化でバーの幅が毎秒変わらないようにする。
- **段階の境目**：2 期の指標（温度・周波数・ディスク I/O・ネットワーク）は、設定画面に出さない。

## 3. 実装上の追加事項

- バーのウィンドウに `WS_EX_TOOLWINDOW` を付け、Alt+Tab の一覧に出ないようにする。
- 2 回目に起動したとき：Mutex で重複を検出したら、名前付きパイプで起動中のインスタンスに知らせ、バーを表示させてから終了する。こうしないと、バーを隠している状態で利用者が「起動しない」と感じるため。
- 容量の単位は 1024 進で、表記は `GB`（タスクマネージャーと同じ）。
- ディスクは固定ドライブ（`DriveType.Fixed`）だけを対象にする。ネットワークドライブやリムーバブルドライブは、`IsReady` の確認で処理が止まることがあるため。
- フォントは `Segoe UI, Yu Gothic UI`（日本語の文字は Yu Gothic UI で表示される）。
- ログ：`Microsoft.Extensions.Logging` には、ファイルに書き出す機能がない。依存パッケージを増やさない、小さなローテーション付きロガー（`RollingFileLog`）を自作した（§4）。
- パフォーマンスカウンターは PDH API の `PdhAddEnglishCounter` で読む。.NET の `PerformanceCounter` は表示言語に合わせた名前が必要なうえ、この PC（日本語版 Windows）では `GPU Engine` カテゴリーが一覧に出ないため（2026-10-22 に確認）。
- GPU 使用率の計算はタスクマネージャーと同じにする。エンジンごとに全プロセスの使用率を合計し、そのうち最も高いエンジンの値をアダプターの使用率とする（`GpuCounterMath`）。
- GPU の識別子：設定には、再起動しても変わらない `VEN_xxxx&DEV_xxxx&SUBSYS_xxxxxxxx&REV_xx`（同じカードが複数あれば `#n` を付ける）を保存する。カウンターとの対応付けには、起動ごとに変わる LUID を使う。自動選択では、ソフトウェアのアダプターを除き、専用メモリが最も大きい GPU を選ぶ。選んだ GPU が見つからないときは自動選択に切り替え、そのことをツールチップに表示する。
- 取得元ごとの失敗：1 つの取得元（CPU・GPU・メモリ・ディスク）が例外を出しても、ほかの取得元には影響させない。失敗した取得元は 5 秒から 60 秒まで、間隔を倍にしながら再試行する（`CompositeMetricsSource`、`FailureBackoff`）。
- ツールチップには、値の取得元（GPU 名）、値が取れない理由、取得時刻を表示する（v1.0 §12-1）。
- 開発用に、起動オプション `--simulate` を付けると模擬データで動くようにした。

## 4. 段階 C で決めたこと（2026-10-22）

- **起動時に設定を書き出す**（KOU が決定）：起動のたびに、正規化した `settings.json` を書き出す。ファイルが無い場合や、壊れていて退避した場合でも、起動後には必ずファイルがある。範囲外の値も、起動時に直した値で書き戻す。
- **自動起動の初回案内はしない**（KOU が決定）：初回起動のときに、自動起動についての通知もダイアログも出さない。自動起動は、トレイメニューか設定画面で利用者自身がオンにする。初期状態はオフ。
- **自動起動の状態はレジストリを正とする**：`HKCU\...\Run` に値 `SysMonitorBar`（exe の絶対パスを引用符で囲んだもの）を書く。タスクマネージャーや Windows の設定の「スタートアップ アプリ」でオフにされた状態（`StartupApproved\Run` の先頭バイトの最下位ビット）も、オフとして扱う。起動時とトレイメニューを開いたときに、レジストリの状態を設定ファイルとメニューに反映する。アプリからオンにしたときは、「スタートアップ アプリ」でオフにされていた印も消す。
- **exe を移動したときの修復**：登録されたパスの exe がもう存在しないときだけ、今の exe のパスに書き換える。別の場所にある別のコピーがまだ存在する場合は、書き換えない。
- **モニターごとの DPI に対応する**（PerMonitorV2）：バーの位置は、物理ピクセル（`leftPx` / `topPx`）で保存する。段階 A の `leftDip` / `topDip` は、初回起動時に「システム DPI の倍率」を掛けてピクセルに直し、以後は書き出さない。バーの最大幅は、モニターの作業領域（ピクセル）÷ バーの DPI 倍率で、DIP に直して決める。DPI が変わったとき（`DpiChanged`）は、最大幅と位置を計算し直す。既定位置の上の余白（16 DIP）も、DPI に合わせて拡大縮小する。
- **スリープと復帰**：スリープに入るときはサンプリングを止める。復帰したときは、取得元を作り直す（PDH のクエリーを開き直し、GPU アダプターを一覧し直す）。GPU ドライバーのリセットで LUID が変わることがあるため。
- **ログ**：`%LocalAppData%\SysMonitorBar\logs\SysMonitorBar.log` に書く。1 ファイル 2 MB、全部で 5 ファイル、Info 以上を記録する。主な記録内容は次のとおり。毎秒の測定値は書かない。
  - 起動と終了、設定ファイルの状態
  - 使っている GPU
  - 取得元の失敗と回復
  - 自動起動の変更
  - スリープ、復帰、画面構成の変化
  - 処理されなかった例外（UI スレッドで起きたものは、記録したうえで動作を続ける）
- **長時間運転の確認**：`tools/soak.ps1` で、メモリ・ハンドル数・スレッド数・CPU 使用率を CSV に記録する。

  | 圧縮なし（採用） | 約 165 MB | 約 113 MB | 約 43 MB |
